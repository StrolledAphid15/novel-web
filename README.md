# 页间 · 小说阅读器

一个可在手机、平板和桌面浏览器使用的轻量小说阅读器。无需安装依赖，直接用现代浏览器打开 `index.html`，或在项目目录运行：

```powershell
python -m http.server 8000
```

然后访问 <http://localhost:8000>。

支持 TXT、Markdown、EPUB 导入，浏览器本地保存书籍和阅读位置；提供章节导航、字号、三种阅读主题，以及 JSON 备份导入导出。EPUB 渲染使用开源 [epub.js](https://github.com/futurepress/epub.js) 和 [JSZip](https://github.com/Stuk/jszip)，固定版本随应用保存在 `vendor/` 并预先离线缓存，只在打开 EPUB 时按需执行；第三方许可证也保存在该目录。阅读界面字体使用本地文件并随应用缓存，界面字体来自 Google Fonts，连不上时回退到系统字体且不阻塞首屏。

触屏阅读时，上滑到章末后，松手再上滑一次进入下一章开头；下滑到章首后，松手再下滑一次回到上一章底部。短章节或打开时已在边界，也需先滑一次，再滑第二次切章。滚轮阅读时，滚到边界后停止滚动，再向对应方向滚动一次即可切章。正文文字和阅读区空白处均可操作，支持 TXT、Markdown 和 EPUB，并保存切章后的阅读位置；第一章不能继续后退，最后一章不能继续前进，同一次滚动或滑动到达边界时不会立即切章。

## 安装为应用

网站通过 HTTPS 访问时，可在 Microsoft Edge 打开后，从浏览器菜单选择“应用”→“将此站点安装为应用”，或使用地址栏中的安装图标。安装后会以独立窗口运行；书架和书籍保存在浏览器本地。首次使用或升级后，先联网打开一次并等待应用资源缓存完成，此后断网也能重新打开页面、阅读本机的 TXT、Markdown 和 EPUB（包括本机尚未打开过的 EPUB）、切换章节并保存阅读位置。页面请求失败或超过 3 秒时回退到缓存，脚本、阅读组件和字体优先使用本机缓存。

“我的书架”中的书可直接离线阅读；从“云端书库”打开已下载的书也直接使用本机正文，无需连接 GitHub。尚未下载的云端书籍和 GitHub 同步仍需联网，离线阅读记录保存在本机，可在联网后同步。离线重开页面需要浏览器支持 Service Worker（HTTPS 或 localhost）且保留本站数据；直接通过 `file://` 打开时，需要本机项目文件完整。

首次打开一本 EPUB 时会先显示正文，再在后台建立全书位置索引，因此进度百分比可能先按章节估算、随后自动校正；索引生成后会被缓存，再次打开无需重建。

## GitHub 同步

### 两位读者共用书库

页面右上角可切换“纨絔”和“澪”，当前选择只保存在此设备。两人共用书籍文件、书名和作者；阅读位置、最近阅读的书、字号和主题按读者分别保存。同一位读者在不同设备上选择同一档案，即可同步自己的记录。名字可在同步设置的“读者档案”中修改，改名不影响已有记录。

同步后，侧边栏的“我的书架”只显示当前设备已经下载的书；“云端书库”显示同步清单中的全部书籍。点击云端书籍才会下载正文并打开。书籍清单会缓存到本机，断网时仍可查看上次同步的目录。书架中的“移出设备”和设置中的“移出本机书籍”只删除本机正文，不删除云端书籍或任一读者的阅读记录。

云端书库卡片提供“删除云端”操作。确认后会删除共享云端书籍文件、清单记录和两位读者对应的阅读记录，并传播到其他设备；只想清理当前设备时，应使用“移出设备”。

升级后，本机和云端旧版进度、偏好自动归入“纨絔”，“澪”初始没有阅读记录。首次连接时，应用从设置中的基准分支（默认 `main`）创建 `sync-books`、`sync-reader-a` 和 `sync-reader-b` 三个分支，以继承现有数据。之后书籍清单和正文写入 `sync-books`，读者数据分别写入各自分支的 `sync/readers/reader-a.json` 和 `sync/readers/reader-b.json`。请让所有设备都更新到新版后再同步。

删除、清空书库会影响两人，并通过同步传播到其他设备；替换书籍文件会重置两人的阅读位置。新版 JSON 备份包含书库和两份读者档案，导入会替换本机数据；旧备份的进度和设置归入“纨絔”。读者档案没有密码隔离，拥有数据仓库访问权限的人可以读取两人的数据。

建议为阅读器数据创建一个专用私有 GitHub 仓库，并初始化默认分支：

1. 创建私有仓库，例如 `novel-web-data`，初始化 `main` 分支。
2. 创建 Fine-grained personal access token，只选择该仓库，并授予 Repository permissions → Contents → Read and write。
3. 打开阅读器设置，填写 `owner/repository`、分支名和 token，点击“连接并同步”。

同步文件放在仓库的 `sync/` 目录。首次同步会上传本机书籍或下载云端目录；后续用 SHA-256 内容哈希核对本机已有书籍，只传新增或内容变化的书。云端清单只保存书籍元数据和内容哈希，书籍正文按需读取；阅读进度和偏好放在各自的读者文件中。书籍与两位读者数据分别写入三个分支，以减少不同数据更新之间的冲突；同一分支上的并发写入仍通过重读和重试处理。已配置 GitHub 的设备每次打开或刷新网页时会自动静默同步一次，仍可点击“同步”或“连接并同步”手动同步；遇到跨页面锁或云端并发更新时会在 2 秒后重试。自动同步不弹提示，失败时可在同步设置中查看状态。真正从云端删除书籍仍使用清单删除标记传播到其他设备；移出本机不会产生删除标记。

每台设备首次都要填写同一个仓库和 token，之后凭据会保存在该设备浏览器中，供启动时自动同步使用；阅读中需要立即同步时可手动点击同步按钮。token 保存在当前浏览器的 `localStorage`，可以被此网站运行的脚本读取；不要把它写进源码或提交到仓库。为 token 设置到期时间并限制到专用私有仓库。删除文件会产生新的 Git 提交，旧版本仍留在仓库历史中。本机 IndexedDB 仍是阅读时的数据来源；首次在新设备同步需要下载书籍。JSON 导出/导入仍可用于额外备份。

GitHub API 在不同网络环境下的连接速度可能不同；Contents API 单文件上限为 100 MB，EPUB 编码后的备份超过此大小会上传失败。

## 代码结构

项目使用普通 JavaScript 脚本模块，无需安装依赖或构建。`index.html` 按顺序加载各模块，`app.js` 创建应用状态、装配模块并绑定页面事件。

| 文件 | 职责 |
| --- | --- |
| `js/model.js` | 书籍与读者合并规则、文本解析、备份编码和内容哈希 |
| `js/storage.js` | IndexedDB、localStorage 和旧设置读取 |
| `js/profiles.js` | 读者进度、档案保存和旧数据迁移 |
| `js/ui.js` | 书架、云端目录、设置和状态提示 |
| `js/reader.js` | 选择阅读适配器、主题和字号入口、共享手势及阅读器生命周期 |
| `js/reader-text.js` | TXT/Markdown 章节渲染、章节导航、滚动位置保存与恢复 |
| `js/reader-epub.js` | EPUB 解析、目录与 CFI 定位、iframe 样式和资源清理 |
| `js/github.js` | 使用一次操作的仓库与令牌快照调用 GitHub API |
| `js/sync-model.js` | 生成同步计划、合并正文与书籍信息、删除标记和读者记录的纯数据规则 |
| `js/sync.js` | 执行同步计划、网络和本地读写、跨页面锁、冲突重试、下载和云端删除 |
| `js/library.js` | 导入、编辑、移出本机、打开书籍和备份操作 |

IndexedDB 使用 `yejian-reader` 版本 2：`books` 保存书籍信息和章节数，`bookContents` 保存 TXT 正文或 EPUB 文件及定位缓存。旧版完整书籍会在一次升级事务中自动拆分，原有读者进度继续保留；升级失败时事务会回滚。升级时需关闭其他仍使用旧数据库的阅读器页面。

书架和搜索只读取书籍信息，打开书籍时加载对应正文；正常启动不再重写整库。同步使用已缓存的内容哈希，只有需要计算哈希或上传正文时才读取本机正文，只写入实际变化的书籍。JSON 备份仍导出完整正文，备份版本 2、云端清单版本 3 和三个同步分支沿用原有格式。

阅读位置先更新内存，连续滚动及 EPUB 定位最多每 500 毫秒合并保存一次；切章、切书、切读者、导出备份、开始同步、页面隐藏或离开页面时立即保存。模块通过参数传入状态和依赖，阅读器临时状态与同步运行状态分别保存在模块内部。

同步规则模块不访问网络、存储或页面，时间由调用方传入；`sync.js` 取得传输结果后再调用规则模块生成最终书库。TXT 和 EPUB 适配器各自管理章节与异步恢复状态，通过 `open`、`close`、`selectChapter`、`moveChapter` 等接口接入统一阅读器；应用其他模块通过 `reading.saveProgress()` 保存当前格式的进度。

新增或修改入口脚本时，应同步更新 `index.html` 与 `sw.js` 中的资源清单及缓存版本，让 PWA 离线缓存包含所有模块。
